# TensorFold: independent source and optimization audit

Owner: live_state_audit. Parent: execution-fabric / model-execution. Research date: 2026-10-21.

## Result

- The authoritative inference project is [ashhart/TensorFold](https://github.com/ashhart/TensorFold), linked by [tensorfold.dev](https://tensorfold.dev/). This audit pins main `d1018b318fb51981c4a18f12e40269a4d3ee9713`, committed 2026-10-19; latest release inspected: `v1.1.1`, 2026-10-19. Metadata is retained beside this report. No associated inference paper was identified in the primary-source search; this is a code/docs audit, not a paper reproduction.
- Current main is native Zig with direct Metal/CUDA kernels. Python/MLX `v0.6.6` is frozen historical code. Old SmartTensor memory-streaming descriptions are a third, older lineage; they must not be presented as current native Qwen capabilities. [Current contributor contract](https://github.com/ashhart/TensorFold/blob/d1018b318fb51981c4a18f12e40269a4d3ee9713/CONTRIBUTING.md#L1-L5)
- Reuse the mechanisms, not another inference engine: closed fusion, fixed reduction layouts across verification widths, amortized dispatch, preallocated storage, adaptive proposal pricing, complete hybrid prefix snapshots, and bounded copy staging. The detailed inventory covers architecture, arithmetic/layout, speculative execution, scheduling, memory, offload, compilation, parallelism and validation.
- Preserve the current order: genuine vLLM numerical/source/state/natural-feedback parity for .8B/2B; matched short concurrent performance; then Qwen 27B and Gemma4. TensorFold's speedups do not justify changing an accepted arithmetic profile or resource envelope.
- No TensorFold code was built or run. No models, SDKs or binaries were acquired. No benchmarks, full-model inference, memory measurements or implementation qualification were performed by this research agent.

## What its execution architecture actually does

TensorFold has shared lane control and family-specific math implementations. Its [lane engine](https://github.com/ashhart/TensorFold/blob/d1018b318fb51981c4a18f12e40269a4d3ee9713/zig/src/core/lanes/engine.zig#L104-L215) selects live streams, gives least-recently-served streams bounded shared rounds, verifies proposals and keeps accepted paths. Its per-family forward executes embedding, normalization, GDN/attention, MLP and head using model-specific kernels. This is substantial reuse, but not evidence of a universal algebraic fusion compiler.

For us, these are compiler/dispatch policies within the existing `run_layer_sequence` → `PlanBuilder` → `ForwardPlan` → `ResidentProgram` loop. They do not warrant embedding Zig/Python, adding a second traversal, or introducing a new source/session/root issuer. Pipeline scaffolds and routes remain clients of the same mathematical engine; they cannot turn source-free shape metadata into execution authority.

## Exactness: the important contract difference

TensorFold explicitly requires drafted=plain, resumed=fresh and concurrent=solo within the same engine/backend/settings. Changed reductions may pass against an independent FP64 error bound, rather than reproduce stock-runtime bits. Model fidelity checks are separately teacher-forced and report top-token differences/margins. [Exactness and precision rules](https://github.com/ashhart/TensorFold/blob/d1018b318fb51981c4a18f12e40269a4d3ee9713/CONTRIBUTING.md#L32-L50)

That is not our current pinned vLLM BF16 CUDA numerical contract. For example, the [native 2B recipe](https://github.com/ashhart/TensorFold/blob/d1018b318fb51981c4a18f12e40269a4d3ee9713/docs/recipes/qwen3.5-2b-native.md) warns that its FMA, reduction and attention choices differ from stock MLX, although lane widths reproduce one another. The [Gemma native recipe](https://github.com/ashhart/TensorFold/blob/d1018b318fb51981c4a18f12e40269a4d3ee9713/docs/recipes/gemma-4-native.md#L1-L45) distinguishes a reference split-K from a faster default that can move BF16 values. Its ANE prompt path is disabled by default because FP16 changes replies. [Current change record](https://github.com/ashhart/TensorFold/blob/d1018b318fb51981c4a18f12e40269a4d3ee9713/CHANGELOG.md#L55-L95)

Our reusable rule: optimize physical execution while preserving required casts, FMA/reduction order, phase-specific layout and complete state. If a candidate intentionally changes those, it needs an independently named numerical profile and fidelity acceptance, not a tolerance or near-tie waiver applied to the current parity gate. Width invariance is valuable within one qualified phase; it must not erase an original runtime's genuine prefill/decode differences.

## Priorities after parity: concrete units

These are proposals, not implementation or speed claims. Every unit preserves the old qualified path and gets its own real source/state/cancel/physical validation plus complete `scripts/check.sh` before acceptance. ROOT controls execution and shared plans.

1. **Stable cold storage and actual natural per-call binding first.** Finish the existing same-engine natural publication/binding prerequisite. Do not overwrite accepted immutable teacher descriptors, reset `OnceLock`, allocate after native activation, or manufacture `RootReady`. Actual packet ID → source-owned row upload → fresh immutable call wrapper must retain the original service/attempt/slot and complete before root commit. This is correctness work already in progress, not a TensorFold-inspired alternative engine.
2. **Profile the real full model, then reduce host dispatch.** The actual forced proof has 6,787 dispatches; it does not tell us how much of wall time is launch overhead. Measure ordinary natural prefill/decode, diagnostics removed only under verified output/state contracts. Reuse the original actor, cold library and packet; no mandatory D2H/full-state comparison in the timed product hot path. Keep the comparison path for acceptance.
3. **Closed equation-preserving fusion.** Start with original residual/RMS stage sequences and adjacent pointwise producer/consumer regions. Preserve unrounded F32 residual sum, BF16 side output and exact selected normalization reduction. Then consider QK/RoPE/store and GDN packing/tail regions. Never fuse across StateEffects without an explicit effect/ownership contract. Full-logit/all42/next-token checks decide; fewer launches alone do not.
4. **Bounded graph replay for actual natural phase shapes.** Reuse current capture/fence/real-completion machinery; key by immutable source, numerical profile, phase/geometry, original workspace generations, kernel/library identity and storage binding. Admit graph native memory before capture, retain encoded readers and reject stale bindings. Fault capture, replay, cancellation, failed retirement and source replacement. Preserve eager fallback only when it is itself safe and numerical-equivalent.
5. **Remove duplicate cold source staging, then add liveness-based private storage reuse.** Actual cold source windows retain authenticated chunks. Deduplicate only with proven same issuer/chunk/generation and ticketed owner sharing. Derive physical liveness from the same plan; do not alias externally retained values, prior/candidate roots, encoded/captured readers or concurrent calls. Compare real peak reservation and allocator backing, not only logical Vec lengths.
6. **Dynamic shared rounds under original fair workers.** Existing native/GGUF batch foundations are not arbitrary HF temporal batching. Qualify per-phase rows and ragged layout with source/status/all-state closure, then admission/fairness/TTFT/ITL for C1/2/4/8 using fixed populations. Price full rounds and request latency; preserve prompt progress and cancellation, not only aggregate tokens/sec.
7. **Complete hybrid prefix reuse/COW.** Cache only genuinely published roots. Identity includes source/loader/quant/numerical profile, actual token/template/position/processor/tenant and all required domains. Restore the greatest common valid frontier across Conv/H/KV/draft/grammar, not the longest KV match. Compare restore versus recompute and test corrupt/stale snapshots and unknown copy completion.
8. **Proposal-only n-gram/Recall before new drafter acquisition.** A bounded local proposal source has low extra model memory. It still needs target verification, exact sampling semantics and all-domain rollback for each acceptance length. Start only after actual natural model execution; no accepted proposal may bypass the target. MTP/DFlash follows when actual source/taps/head/cache resources and model-specific licenses are bound.
9. **27B capacity path, not an assumed resident speedup.** Our current 5GiB owned-device envelope and RTX3060 Laptop cannot hold the original ~55.56GB 27B source. Streamed dense weights require a full bandwidth/IO/admission design; MoE hot-expert caching does not make this dense model sparse. A low-bit source is a separate derived/third-party identity and fidelity profile. Source-only window qualification is reusable but is not streamed inference.
10. **Gemma4 after its actual source semantics.** Reuse the engine and operator infrastructure, but bind the right E2B/26B/31B model. Gemma-specific GeGLU, scaling/softcap, SWA/global geometry, PLE/MoE/K=V/MTP dependencies cannot be imported from the unrelated 12B native recipe. Metal/ANE mechanisms are later hardware-specific candidates; the local AMD launch hold remains.

## Ways we might improve beyond the borrowed mechanisms

All are hypotheses requiring measurement; none establishes that we outperform TensorFold, vLLM or another engine.

| Hypothesis | Minimal same-engine implementation / decisive evidence |
| --- | --- |
| A certificate for each optimized closed region can combine exact source, phase, arithmetic, layout, state effects and physical ownership. | Store a small accepted candidate key in the existing executable plan; refuse unknown regions. Mutation tests must catch wrong rounding, source, row tails and writes. This can avoid broad family-specific permission flags. |
| Joint cache/proposal scheduling can choose better useful work than acceptance rate alone. | Optimize measured expected committed tokens under TTFT/ITL/fairness and original host/device/IO caps, charging rollback/copy/DFlash costs. Compare policy against no-draft and fixed-depth controls under matched workloads. |
| Immutable authenticated chunk sharing can lower cold host peak without relaxing source proof. | Share the same verified chunk owner across overlapping gamma/embedding/parameter windows; prove cancellation/last-drop/rename/mutation behavior and actual peak retirement. Do not substitute metadata equality for issuer equality. |
| A liveness-aware arena can retain independent StateRoots while shrinking diagnostic-style full-value retention. | Reuse only private nonoverlapping intervals after the last real/captured reader; inject abort at every reuse boundary and verify exact fullV/all42. Savings are actual allocator/reservation differences, not summed payload estimates. |
| Distinct-matrix/full-round cost models can prevent microbenchmark cache and fusion mistakes. | Benchmark each actual source matrix once in its layer sequence, cold/warm state named, then matched complete requests. Include dispatch, memory traffic, state transport, graph mode and physical headroom in the candidate key. |
| Full-state prefix checkpoints plus cheaper reconstructible domains can improve capacity. | Recompute only from a genuinely restorable earlier root; cost the needed GDN/Conv/KV replay and preserve all teacher/position lineage. Compare against complete snapshot restore; no inferred KV-only frontier. |
| Phase-specific row-invariance gates can allow safe speculation without imposing one sum order on all phases. | Certify the reference-equivalent width family separately for prefill, continued prefill and decode. Test mixed streams and every partial keep, full state and next logits. Reject a width that changes the accepted profile. |
| Finite background IO/compilation budgets can prevent optimization from harming latency. | Reuse original fair worker admission; foreground prefill/decode owns priority, bounded background restore/prefetch/autotune consumes explicitly admitted slack. Test cancellation and saturation instead of relying on idle sampling. |

## What not to copy automatically

The composition boundary is the existing Rust execution spine, not a new runtime for each optimization:

| Stage | Composable mechanisms | Authority that must remain unchanged |
| --- | --- | --- |
| Request → exact tokens/positions | Stable template-aware chunking; source-bound integer positions; bounded proposal lookup | Original request/source/teacher/phase issuer. A proposal or cache lookup cannot retag the actual input. |
| Tokens → canonical typed plan | Source-owned model schedule; transient legal fusion/layout choices | Same `run_layer_sequence`, `PlanBuilder`, numerical profile and explicit StateEffects. |
| Plan → prepared storage | Byte-preserving packing; authenticated chunk sharing; liveness reuse; complete-domain COW; bounded prefetch | Original `SourceIdentity`, independent StateRoots and physical host/device/IO admission before allocation. |
| Prepared plan → issued work | Fair shared rounds; keyed graph replay; closed fused kernels; optional hardware-specific tiling | Same actor/queue, exact original handles/stream/generation and all encoded/captured/in-flight owners. |
| Work → trusted completion | Device finite/status checks; small BF16 greedy packet; admitted copies/readbacks | Original real completion/quarantine. No logical counter, process exit or timing sample synthesizes Ready. |
| Completion → public next request | One all-domain root commit, actual emitted ID feedback; optional complete snapshots | Original `ResidentSession` publication, current attempt/epoch and incomplete-prefill emission rule. |
| Telemetry → future policy | Full-round width/depth/restore cost models and bounded offline candidate selection | Cost metadata has no source/state authority and cannot relax a failed numerical/physical gate. |

Specific combinations worth evaluating after parity:

- **Prepared natural bindings + graph replay + closed fusion:** stable storage removes late allocations; graph replay removes CPU launch overhead; fusion removes device transitions/intermediate traffic. Their gains overlap, so test each and the combination at full-request level rather than add microbenchmark speedups. Each fused graph has its own accepted kernel/layout/reader key.
- **Complete hybrid prefix COW + shared rounds + speculative rollback:** prefix reuse reduces repeated prefill, batching amortizes source reads, and target verification may advance several tokens. They compete for state/scratch/IO and can worsen TTFT. Use one joint admitted budget and retain a genuinely restorable common frontier; no KV-only hit or partial branch root is public.
- **Authenticated source placement + liveness arena + graph-stable handles:** coalesce or share cold source chunks first, choose bounded physical slots once, then pin readers through captures. Prefetch/eviction must respect that pinning; an arena cannot recycle a slot merely because the host plan moved on.
- **Qwen27 dense streaming + prompt layer reuse:** more prompt rows can amortize each streamed layer's source transfer, but decode still needs all dense weights. This differs from MoE expert hotsets. Measure SSD/host/device transfer and scratch overlap before choosing tile size; the original5GiB owned envelope is not relaxed.
- **Gemma MoE expert locality + dense-branch overlap:** grouping improves weight reuse only when repeated expert IDs and occupancy justify it. Preserve an independent dense branch when fusion serializes useful work. The actual Gemma source graph decides this; a generic MoE diagram does not.

Incompatible combinations need separate profiles: stock-vLLM bit parity versus alternate K reductions/attention partitions; original BF16 versus FP8 KV/activations or FP16 ANE; original source versus quantized/edited checkpoint; complete dense resident execution versus demand-paged expert layouts; M5/GB10/RoCE performance versus RTX3060; per-topology rank arithmetic versus a single-rank reference. No report from another research lane can remove these distinctions. Future DeepInfer/NVIDIA-guide opportunities should enter these same stage contracts, then be measured together under one accepted profile.

- A faster K split, alternate attention partition, FP8 KV, FP8 activations or FP16 ANE computation is not an exact-profile optimization until proved against that profile. Quantized weights also require their own exact source codec and fidelity qualification.
- “Pinned host cache,” OS-memory reserve fractions, logical device-buffer counters and sampled memory are not replacements for the original physical `ResourceArbiter`, original ledger charge or uncertain-work quarantine.
- Prompt compaction rewrites input semantics; living-weight/checkpoint editing rewrites source semantics. They are optional product/model features, not vLLM parity optimizations.
- TensorFold's two-Mac speed-up example replicates the full model on both machines. It does not solve a single-card 27B capacity problem. NCCL/RoCE, M5 tensor units, ANE and Metal keepalive have no automatic applicability to this host.
- Do not broadly port persistent kernels, grouped expert unions or shared-expert fusion because a diagram has fewer launches. Its own guide records multiple whole-model regressions from those ideas.
