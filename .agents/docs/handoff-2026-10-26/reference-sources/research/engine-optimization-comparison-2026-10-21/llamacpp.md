## Finding and execution boundary

llama.cpp supplies useful **mechanisms**, not an engine to embed. The strongest near-term candidates are source-profiled prefill kernels, fewer materializations/launches, safe prepared/captured execution, and scheduler/residency composition. Its hybrid state, checkpoint and speculative implementations also expose prerequisites that a transformer-only KV design misses. Each mechanism below attaches to the existing source → typed ForwardPlan → numerical lowering → placement/residency → physical queue → private StateRoot → readout path. Do not introduce GGML's allocator, a second state authority or a foreign model loop.

This was read-only research. No foreign engine, model, kernel, build, benchmark or device was executed; no model/SDK/executable was downloaded. All upstream performance figures remain source-author reports. Local acceptance is inherited only from the explicitly scoped current source/tests/plan records, not established anew by this report.

Local inspection root: `/home/pvl/spaces/abird/src/zerogravity-worktrees/root-lowest-f32-20261020`; Git HEAD `fb68d8fa165de16e21d1bd37afef3790b80da971` **plus existing overlays**. Git IDs alone do not describe those overlays. Root README retained blob `a7be69c35cf61d14e8810f9cb5a6a43d1397bf27`.

Current coordinator boundary supplied with this task: original HF BF16 0.8B forced five-phase/full24/all42/full-vocabulary/five-greedy isolated same-engine work exists; natural publication, serving integration and full vLLM parity remain open. Original 2B natural-reference capture is underway. Original 27B source caching/window verification is not runtime support. Gemma4 has contracts, not a qualified trained runtime. Existing GGUF source profiles, earlier llama.cpp references and the BF16 original-source work must remain distinct.

Hardware boundary: SM86 RTX3060 Laptop, 6GiB nominal VRAM, approximately 5GiB operator device bound; allocator/driver/graph/transfer overhead must fit inside real admission. No inference that SM86 hardware support qualifies a particular tensor-core arithmetic profile. Renoir/gfx90c launch/reset/recovery hold persists.

## Local evidence legend

- **T** — accepted/tested in the named existing bounded scope; no fresh run here.
- **P** — partial: a working mechanism exists, but relevant profiles, shapes, integration or complete acceptance remain open.
- **I** — isolated operator/diagnostic implementation; no whole-model/publication/serving permit.
- **D** — design, proposal or unaccepted integration; presence of source is insufficient.
- **A** — applicable mechanism absent from the inspected execution/serving path.
- **N** — inapplicable to current Qwen/SM86 slice; may be useful for a later source/hardware target.

`L01`–`L15` refer to the source/test audit below. A row can have multiple statuses because a leaf may be accepted while its generalization remains open. Upstream status **M** means implemented at the inspected main pin; **EXP** means upstream marks the route experimental; **PR** means still open and excluded from shipped capability claims.

## Arithmetic and state consequences

Optimization is not a license to change the execution profile. GGUF Q4_0×Q8_0, Q4_1×Q8_1, Q6_K×Q8_K, CPU tinyBLAS/OpenBLAS, BF16 original-HF and GPU tensor-core paths can read the same conceptual model and produce different bits because activation encoding, FMA chains, paneling, padding, cast points and recurrence grouping differ. Current main itself changes reductions and eligibility. Keep artifact identity, model semantic identity, execution numerical profile and process-local SourceIdentity separate. [Quantized CPU arithmetic][u_x86q], [MMQ][u_mmq], [current tiled reduction change](https://github.com/ggml-org/llama.cpp/commit/3dbcb7fca56ab4769bd4af684a432e2331bc9ace).

The current Rust [source accumulation policy](/home/pvl/spaces/abird/src/zerogravity-worktrees/root-lowest-f32-20261020/crates/zerogravity-gpu/src/source_accumulation.rs) keeps `WideF64` for the accepted original GPU providers after measured native-F32 FMA mismatches; `NativeF32` remains a qualification-only candidate. This is measured profile evidence, not universal FP64 emulation of IEEE FMA. Optimize or replace it only after the named physical edge/trained/full-state gates; tensor-core availability alone does not supersede it.

The GDN MMA source is especially relevant: its selector requires Hk16, H16/32/48/64 and at least64 tokens; the CUDA whitelist names Ampere GA10x/Ada/Blackwell/DGX Spark, while HIP only enables RDNA3.5 with at least2048 tokens. It also checks shared-memory feasibility and occupancy before choosing split-value layouts. BF16 high/low decomposition is **not** a proof of exact F32 recurrence. Retain the AR fallback as a separately qualified profile; do not use a capability flag as an exactness proof. [Selector and arithmetic][u_gdnmma].

The same caution applies to upstream prompt caching: its API explicitly allows different logits when prefill versus decode batching changes backend arithmetic. Zerogravity's exact profile must instead bind the original computation schedule, or explicitly qualify a different profile/quality policy. Reusing a complete state generated by a different profile is not transparent. [Prompt-cache API][u_serverdoc].

Hybrid speculation requires **all** state: attention K/V, GDN matrix, conv history, positions/masks and any draft/tap bookkeeping, plus sampler/grammar/RNG state once implemented. Upstream restores recurrent checkpoints and replays accepted prefixes when arbitrary sequence removal cannot reconstruct the required state. A rollback that only deletes future KV is insufficient. Keep prepared results private until verification and actual completion; rejected/unaccepted branches retain their physical owners until real retirement. [Hybrid operations][u_hybrid], [verification/replay][u_serverctx].

## Credible composition hypotheses

All are hypotheses to test against pinned baselines, not claims of universal superiority.

- **One source/two readout needs:** source-identical chat and pipeline consumers share immutable prepared weights and kernels; StateOnly teacher work skips LM head, ordinary generation uses compact greedy, diagnostics request full vocabulary. Keep the same plan semantics and private output roots. This reduces avoidable readout and duplicates without mixing session state.
- **Prefix snapshots + batch buckets + stable graphs:** exact same-source prefixes can use immutable complete snapshots, then compatible rows enter finite B1/2/4/8 workspaces. Reuse a captured body only when its full identity and physical ownership match. Irregular arrivals keep smaller buckets or ordinary dispatch; graph padding is never allowed to advance a stopped row.
- **Shared context text + independent numerical caches:** `ContextOwner` captures explicitly granted committed records at a turn/graph epoch; a tokenizer/model/profile-specific cache may reuse only byte-identical prefixes under that authority. Different models can share the authorized immutable text, not KV/GDN state. Context revocation/generation changes invalidate eligibility before delivery/publication.
- **Decode-protected residency + bounded prefill streaming:** transfer the useful SLRU principle—protect recurring decode assets from one-off prefill—without copying the MoE-only algorithm into dense models. The same ResourceArbiter admits transfer buffers, current weights, future IO and candidate state; queue age/deadlines bound prefetch. A cache hit is beneficial only if its retained bytes displace less valuable work.
- **Speculation + attention/KV reuse + scheduler backoff:** a target block verifier can exploit multi-token kernels and repeated K/V loads, but deeper drafting increases temporary state and can delay another request. Choose depth/batch/graph/residency jointly from measured committed benefit and memory headroom. Exact distribution correction, complete state rollback and output-credit fairness come first.
- **Effective fused lifetime planning:** norm/gate/state-transport fusion and graph reuse may cut traffic together, but the allocator must extend reads through the final fused consumer. Reuse the existing physical layout and completion ownership; do not add a hidden scratch arena because GGML has one.
